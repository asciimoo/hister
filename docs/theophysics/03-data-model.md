# PostgreSQL relational and lifecycle contract

Design specification, not an applied migration. Use PostgreSQL 17 as an initial compatibility target, subject to Hub/DSM inspection; pin an available supported minor and matching pgvector image digest in implementation. UUIDs are application-generated UUIDv7; SHA-256 values are 64 lowercase hex characters checked by `CHECK`. Use `timestamptz` UTC for storage, optimistic `revision bigint >= 1`, and `created_at` on mutable aggregates. Do not rely on implicit JSON semantics for referential integrity.

## Ownership and authorization

Default to separate databases `hister` and `theophysics` on the same PostgreSQL cluster. Hister uses its existing migrations and vector tables. Research migrations manage schema `research`; no cross-database FK or write into Hister tables. Hister integration uses API/adapter calls. Avoid search_path coupling: pgvector initialization in current Hister uses unqualified tables. Provision extensions through a migration/admin role before assigning runtime least privilege; verify startup behavior with that role. Local Bleve remains necessary.

Every research aggregate includes `tenant_id uuid NOT NULL`; join tables use composite tenant-aware FKs. `principal(id,tenant_id,external_subject,role,state)` maps a trusted identity issuer+subject, not just email, to users. `resource_acl(tenant_id,resource_id,principal_id,permission)` controls read/write/review/admin. An explicit shared workspace grants shared visibility. Even equal content hashes cannot leak cross-tenant existence or source counts. Runtime uses tenant context with RLS where feasible; pooled transactions use `SET LOCAL` from verified identity. Background workers must set the same context and are not unscoped superusers. Return 404 for inaccessible IDs.

Index all FK join columns and `(tenant_id,document_id)` memberships. Never index full model output in an uncontrolled JSON expression; extract only query-required fields. Use optimistic revisions on job/rule/collection/placement commands. Maintain a migration checksums table and an immutable application schema version.

## Exact-span and identity rules

Freeze extraction text as UTF-8 bytes before machine claim extraction. Do not normalize or reflow it after spans are assigned. Claim offsets count bytes, not UTF-16 code units or Unicode characters. Verify `text[start:end] == UTF8(exact_quote)` and SHA-256 on insertion and export. Record source page/section locator separately for PDFs/HTML; normalized-text offsets do not claim byte offsets in the original PDF. An OCR quote has OCR provenance and confidence, not literal original-byte fidelity. Store split claims with individual spans; discontinuous support uses multiple evidence spans, never a fabricated contiguous quotation.

Canonicalize URLs conservatively: lowercase host, remove fragment for fetch identity, normalize default port; retain raw URL and meaningful query parameters. Tracking removal is versioned/site-specific. Canonical tags and redirects are proposals verified against content and ownership, not authoritative merge commands. File identity is `(agent/root/file-id)` with aliases and snapshots. Hash dedup shares bytes within permission boundaries, not source origin: two publishers repeating one quotation remain two attributed occurrences with a derivative relation. Author/publisher/date may be unknown. No guessed dates are inserted as exact dates.

## Lifecycles

| Aggregate | Permitted transitions | Guard |
| --- | --- | --- |
| Research job | draft → ready → running → awaiting_review → completed → archived | scope and pipeline validated; completion means all selected stages terminal and review policy met, not proof of claims |
| Research job controls | running → pausing → paused → running; active → cancelling → cancelled; running → blocked → ready | checkpoint writes before paused; failure receipts retained; retry increments stage/execution version where inputs changed |
| Stage/work | queued → leased/running → succeeded, retry_wait, failed, cancelled or needs_approval; retry_wait → queued | lease token + input hash match at completion; dependency success required; max attempts produces failed/dead letter |
| Source | staged → accepted → archived, quarantined or tombstoned; archived/quarantined → accepted; tombstoned → purged | searchable state belongs to per-version map, not source acceptance; purged cannot be restored without backup/reintake; Archive has no automatic expiry and uses explicit location journal |
| Artifact | writing → ready → quarantined → ready or purged; writing → failed | verified durable bytes; purge only at zero live references with all holds checked |
| Hister map | pending → indexing → searchable; indexing → retry/blocked; searchable → stale/removing → removed | ack matches expected version; stale map cannot present as fresh; tombstone filters immediately |
| Review | proposed → needs_review → verified/accepted or rejected → superseded | authorized human acceptance; prior assertions retained; machine verified extraction is separately labeled |
| Deletion plan | staged → executing → completed/partial; staged → expired/cancelled; partial → executing | valid actor-bound approval and unchanged dependencies; expired preview requires regeneration |
| Export | queued → building → ready/failed; ready → superseded | immutable snapshot manifest; concurrent user edits never overwritten |

Cancellation does not undo accepted source writes. Compensation commands produce new receipts. “Falsified” is an assessment, not a source lifecycle transition. Publication scope is `private`, `workspace_searchable`, `approved_collection`, `exported`, `published` with explicit decisions; export does not automatically make source content public. Multiple assessments/statuses may coexist by method, assessor and context.

Epistemic status vocabulary: `mathematically_proved`, `empirically_supported`, `historically_corroborated`, `direct_testimony`, `philosophical_inference`, `theological_interpretation`, `model_dependent`, `speculative`, `disputed`, `unresolved`, `falsified`, `not_presently_testable`. Mathematical proof requires stated axioms/derivation and method-specific review; confidence cannot confer that status. Do not store the status as a single mutable truth attribute on the claim.

## Lease transaction specification

Claim one eligible row ordered by available_at/id inside a short transaction with `FOR UPDATE SKIP LOCKED`; set state running, increment token and attempt, set deadline from database clock, commit. Perform network/model work outside the transaction. Renew only while owner/token match. Completion updates `WHERE id=? AND lease_token=? AND state='running'`; zero updated rows means stale result is discarded. Ack and follow-up outbox events commit together. Recovery requeues expired leases and invalidates old tokens. Logical-key unique constraints and Hister acknowledgments make replay safe. Job pause updates policy revision so workers recheck before committing an externally consequential result.

## Product-specific lifecycle distinctions

[The desktop-first contract](00-product-contract.md) governs categories, duplicate groups and `999_ARCHIVE`. Category assignment does not imply an approved hierarchy placement. Ordinary high-confidence policy assignments are reversible; medium assignments are provisional/review-required; low proposals remain pending; Unknown falls back to Inbox/Workbench. Archive plans maintain one authority pointer per source version plus explicit replica locations and recoverable filesystem journal state. Archive state is not deletion quarantine and is not eligible for time-based purge.
